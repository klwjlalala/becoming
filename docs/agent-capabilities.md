# 通用 Agent 能力扩展

本模块不定义某一种固定 Agent 角色。角色、任务流程和交付要求由用户在会话中提供；运行时负责保留指令、发现工具、执行能力并渲染结构化结果。

## 会话级自定义指令

- 首轮消息包含明确角色标题（例如 `Role:`、`角色设定：`）及多项任务约束时，会自动固定为本次会话指令。
- 固定指令独立存储，不受最近 12 轮聊天历史窗口影响。
- 使用 `/set-instructions\n...` 替换当前会话指令。
- 使用 `/clear-instructions` 清除当前会话指令。
- 原始提示词仍保留在聊天记录中，但不会在每轮上下文里重复注入；对应的助手回复仍保留。
- 自定义指令始终受系统安全、隐私和更高优先级规则约束。

## 成果连续性与增量修订

系统提示词增加了通用成果生命周期约束：识别用户明确指定的交付阶段和确认门槛；成果交付后，判断后续补充是否影响已有结论；需要时局部修订或重新整合；用户结束任务时先检查是否仍有明确交付未完成。普通闲聊不触发成果重写。

当前版本由模型结合最近对话上下文维护成果状态，**尚未建立独立的持久化成果版本库**。Agent 默认只把最近 12 轮对话放入模型上下文，因此跨越较长对话窗口后，旧成果的完整内容仍可能无法直接召回。后续若真实使用证明有需要，再增加显式成果对象、版本和修订记录，不在这一阶段提前引入复杂存储结构。

## 原生工具调用

模型通过 OpenAI-compatible Chat Completions 的 `tools` / `tool_calls` 协议调用工具，不再依赖模型在普通文本中伪造工具 JSON。

`agent-runtime/capabilities/registry.mjs` 提供：

- 工具注册：名称、说明、JSON Schema、类别、关键词和执行处理器。
- 参数校验：类型、必填项、额外字段、枚举、长度和数值范围。
- 动态发现：模型先调用 `discover_capabilities`，再按需激活匹配能力。
- 执行限制：限制单轮工具调用轮数和总调用次数。
- 结果回传：工具结果作为 `tool` 消息交回模型，模型再组织最终答复。

## 已接入能力

| 能力 | 用途 | 条件 |
|---|---|---|
| `chart_create` | 柱状图、折线图、饼图 | 本地可用 |
| `diagram_create` | 关系图、流程关系图 | 本地可用 |
| `image_generate` | 生成场景图、插画等图片 | 需要配置图像模型 |
| 成长记录工具 | 查询、创建、修改和删除成长记录 | 写入操作仍需用户确认 |

成长记录工具沿用现有的确认机制：工具只生成预览，只有用户确认后才真正写入。

## 多模态内容块

每轮消息可以携带 `content_blocks`，与文本一起保存到本地 SQLite：

- `chart`：由前端 SVG 渲染。
- `diagram`：由前端 SVG 渲染，支持节点、连线和关系标签。
- `image`：通过本地资产 ID 展示，不直接加载模型返回的任意远程 URL。
- `document`：预留本地文件资产展示入口。

聊天正文使用安全的 DOM 节点构建 Markdown，不使用模型输出的原始 HTML。

## 图像模型配置

Python 网关读取以下环境变量：

| 变量 | 必需 | 说明 |
|---|---|---|
| `BECOMING_IMAGE_MODEL` | 是 | 图像生成模型名称 |
| `BECOMING_IMAGE_BASE_URL` | 否 | 图像服务 OpenAI-compatible API 地址；默认复用 `BECOMING_BASE_URL` |
| `BECOMING_IMAGE_API_KEY` | 否 | 图像服务密钥；默认复用 `BECOMING_API_KEY` |
| `BECOMING_ASSET_DIR` | 否 | 生成图片的本地存储目录；默认使用数据库路径加 `.assets` |

图像服务需要兼容 `POST /images/generations`，并返回 `data[0].b64_json`。目前接受 PNG、JPEG、WebP，单张图片最大 15 MB。未配置图像模型时，工具会返回明确的未配置错误，不会伪造图片。

配置好图像模型后，可以在 GitHub Actions 的 **Node agent native tool-call probe** 工作流中手动勾选 `probe_image`，执行一次真实出图测试并下载测试图片。该步骤默认关闭，避免在普通 CI 中产生图像生成费用。

## 当前边界

- 原生工具调用已通过当前配置模型的真实调用验证。
- 动态发现、图表和关系图工具有确定性测试及真实模型联调。
- 图片生成链路已接入可选 OpenAI-compatible provider；仍需配置实际图像模型并完成真实图片生成验证。
- 图表与图片块已进入持久化和前端渲染链路；文档生成、联网搜索等能力后续通过注册新工具扩展，不修改 Agent 的角色或主循环。

## 原始 HTML 对话回放测试

为了验证用户给出的复杂提示词能否由通用 Agent 执行，可以在本地回放导出的 HTML 对话：

```bash
node agent-runtime/validation/replay-html.mjs /path/to/人生意义探索_完整对话.html
```

脚本会从 HTML 中提取原始提示词和用户发言，**不会把原对话中的助手回答喂给模型**，避免模型只是复述原答案。随后按顺序将提示词和用户发言交给当前 Agent，记录每轮回答、工具调用、图表/关系图/图片内容块及最终手册。结束时会给出 `passed` 或 `needs_review`，检查首轮节奏、指令持续性、手册篇幅和章节、内容块持久化以及生成图片资产有效性。

- 使用操作系统临时目录中的独立 SQLite 数据库，并在正常结束后清理；不会写入项目数据库或用户现有会话数据库。
- 回放完成后会重新打开 SQLite 和本地资产索引，验证消息内容块、图片元数据及图片文件能否跨进程重启恢复。
- 报告和生成资产保存在本地 `agent-runtime/artifacts/`，该目录已加入 Git 忽略。
- 图片生成默认关闭，避免意外产生图像费用；确认已配置图像模型后，可设置 `BECOMING_ENABLE_IMAGE_GENERATION=1` 开启。默认最多生成 2 张，可用 `LIFE_MEANING_MAX_IMAGE_CALLS` 调整为 0–4 张。
- 默认最多进行 40 次模型调用，可用 `LIFE_MEANING_MAX_CALLS` 调整为 13–100 次；预算耗尽会中止回放并留下报告。
- 这是原始用户发言顺序回放，不会把旧助手提问和回答复制进新会话；若新 Agent 的提问顺序不同，部分回答可能与它当轮问题不完全对应。因此它用于检查原始用户信息序列下的鲁棒性，不等同于逐轮复刻原始对话。
- 验收脚本会在全部回复中寻找最近一次《个人意义设计手册》，而不是把最后一条聊天回复误认为最终文档；文档篇幅、章节、表格和结尾单独检查。
- 如果生成手册后用户又补充了实质信息，脚本会检查最近一次手册是否晚于最后一条实质性用户补充。仅有“没有了”等结束语不算实质补充。
- 模型调用会产生正常 API 用量；启用图像生成还可能产生额外图像费用。

## 真实模型任务验收：人生意义设计

`agent-runtime/validation/meaning-design-acceptance.mjs` 使用虚构的 12 轮对话，验证通用 Agent 能否在会话级指令持续生效的前提下，完成分阶段探索并生成结构完整的《个人意义设计手册》。该用例接入动态能力注册，但默认关闭图像生成，避免测试意外产生图像费用。

本地运行：

```bash
BECOMING_GATEWAY=http://127.0.0.1:8000 npm --prefix agent-runtime run evaluate:meaning-design
```

验收报告会检查首轮提问节奏、12 轮回答保留、长提示词跨历史窗口持续生效、最终手册的章节、篇幅、表格、虚构对话中的关键证据覆盖、是否在用户最后补充前过早交付，以及工具调用失败情况。随后会在独立会话中补充“已掌握 HTML/CSS、只能使用手机”的新约束，检查 Agent 是否真正修订原有的三天 JavaScript 学习计划，而不是只口头确认。它不强制生成图片、图表或关系图；这些能力分别由独立工具调用测试验证。

真实个人 HTML 的回放仍使用 `agent-runtime/validation/replay-html.mjs` 在本地执行。不要将个人对话 HTML 提交到仓库或作为 CI artifact 上传。
