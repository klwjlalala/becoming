# 第三阶段：用户自我理解与探索 V1

## 目标与设计

Becoming 是帮助用户认识自己的 AI 伙伴，不是心理测评或任务管理器。V1 先验证现有同步 Agent + 模型 + 近期对话（以及合并后可选的长期记忆）能否通过明确的交流策略改善实际效果。

- 自然判断交流情境，只有适合时探索；尊重暂停与话题切换。
- 从具体经验、感受、选择、价值观、向往和冲突发现线索。
- 跨经历关联时区分已知证据、用户确认与待验证假设；允许否定、更正及改变。
- 自然提问、阶段总结；不强推目标、任务或行动方案。
- 安全优先，不诊断、不固化人格、不制造依赖。

## 实现边界

新增 becoming/self_exploration.py，becoming/prompts.py 将其追加至原始系统提示词。默认启用交流策略，但每轮是否探索由当前模型判断。既有 Agent.reply、模型接口、CLI、数据库与记忆实现保持不变；无额外模型请求、后台调度、新表、固定画像或阶段状态机。原始提示词保留供评测对照。新策略本身不会扩大历史检索范围，长期记忆检索质量仍由第二阶段负责；不能把提示词约束视为确定性行为保证。

本分支从 main 创建，不依赖尚未合并的长期记忆 PR #1；两者修改文件不重叠。合并后仍需运行组合回归及跨时间效果评测，不能提前宣称集成通过。

## 测试与验收

离线：python -m unittest discover -s tests -v

单独执行真实模型显式功能集成（一次调用，核对策略确实发送、回复与存储）：python -m unittest discover -s tests -p live_self_exploration.py -v

效果评测（虚构数据，真实模型必须显式开启）：

    python -m evaluation.self_exploration
    python -m evaluation.self_exploration --live --case explore-001 --compare
    python -m evaluation.self_exploration --live --case explore-003 --compare --output exploration.json

每个案例独立内存数据库；基线与新版分别从相同用户输入序列运行，后续对话可因回复而不同。评审标准不注入被测 Agent。默认不启用长期记忆；PR #1 合并后可添加 --long-memory，使用综合检索并记录记忆事件。对照两组均使用同一记忆实现，但提取/检索结果可能因真实模型随机性而不同；不等同严格的固定记忆 A/B。模型额度不足时不反复重试。无自动质量评分，人工审核真实对话是否有助于自我理解、是否自然、是否尊重自主性。

验收重点：策略注入及既有主流程正常；显式真实调用能够运行；自然场景能够探索、纠正、停止、不虚构历史；实际质量至少不显著损害普通交流。重大问题修复后推进，不以穷尽所有边界作为下一阶段前提。尚未开展真实效果验证，不宣称质量验收通过。

下一阶段迷茫分析与引导、成长与行动辅助暂不实现。只有实际案例证明现有策略不足，才考虑结构化探索状态或独立用户认知模型。
