# 长期记忆 V1（第二阶段实验实现）

目标：超出近期历史后仍能使用用户明确陈述的相关信息，而非构造人格画像。

## 边界与流程

- opt-in：CLI 使用 --long-memory，默认仍为已验收基础 Agent。单用户、同步、SQLite、无额外依赖。
- 对话前：从活跃记忆以中文二字词、英文词、槽位和类别提示词打分，最多注入5条；无命中不注入。
- 回复成功并保存原始对话后：额外一次模型调用，从当前用户原话提取最多3条 JSON 候选；提供最近30个槽位名称及类别，不提供助手回答。超长输入（8000字符以上）不提取。
- 按原文连续子串、类型、长度、槽位、来源 turn ID 严格校验。批量事务写入；同 key 新内容成为当前版本，旧版保留；同值不重复写入。模型不能直接访问数据库。
- memory event 暴露实际读写 ID 和失败类别；记忆异常不覆盖已完成的正常回复。当前不重试或回填。
- /memories 查看活跃记录；/forget <key> 删除槽位所有版本，原始对话仍可能进入近期上下文；/clear 删除对话并级联删除记忆（即使关闭记忆模式）。两者均为 SQLite 逻辑删除而非物理擦除。
- 用户显式纠正可以由提取器复用槽位；V1 不具备可靠的语义冲突判定、自动遗忘或自然语言删除执行能力。
- 事实、经历、主观陈述为原话引用；认知推断放到后续独立研究，暂不存储推断。

## 未解决的问题

词法检索会漏掉同义、隐含或泛化意图，也可能误召回；槽位由模型生成，可能重复或误覆盖。引用真实性检查不等于语义正确性或长期价值；类别与敏感信息过滤依赖提示词，不能保证完全排除。模型上下文中的历史引用可能包含注入攻击，提示隔离仅为初步措施。当前逐轮提取增加成本和同步等待，活跃集合全量扫描只适合研究原型；旧对话不自动迁移。SQLite 未加密，不适合生产或真实敏感数据。

## 验收

- tests/test_long_memory.py：存储、来源验证、更新、删除、重启、模拟模型链路、异常与原有行为。
- tests/live_memory.py：显式要求真实模型写入、召回、修正，验证执行证据及状态；需授权和模型配置。
- evaluation/cases.json memory-001/002/003：自然场景，人工审核，不将标准注入模型。使用 history_turns=0 隔离长期记忆的贡献；输出记忆事件与活跃记录。尚无效果结论。

## V1.1：记忆质量与控制（实验）

- 提取器比较相关旧槽位的原话与 ID，只有明确修正才提供 replaces；代码要求当前版本 ID 匹配、类别不变。冲突整批回滚、回复保留；同类别同原话跨槽位去重。不是可靠的语义冲突检测，近义重复或模型误判仍可能发生。
- 增加明确长期价值准则及少量明显凭据模式拦截，不能保证隐私检测完备；输入仍可能已经发送给主对话模型。暂不将人为分数当作记忆价值真值。
- 默认词法检索：类别词只能加权，不能单独触发召回。可显式开启 --long-memory --semantic-memory：先词法排序，从最多40条活跃候选（包括零词法匹配）由模型挑选最多5个 ID；仅接受候选内唯一整数 ID，允许空选，错误时不注入并保留对话。最多增加一次调用；候选池以外无法召回，仍需真实对比评测。
- 提取阶段最多发送30条相关旧记录及前100个阻止槽位名称；模型看不到助手回复。超长输入仍跳过提取。
- /forget 删除该槽位所有修订并持久化阻止该 key 再写入；/allow 解除阻止，不恢复旧记录。原始对话、其他槽位的语义近义信息、已发送给模型服务的内容不会删除。换 key 的近义内容仍可能重新记录。/clear 清除对话与关联记忆但保留阻止槽位名称；这是有意保留的用户控制设置，不是物理擦除。
- 不实现自然语言删除、自动时间衰减、跨槽位语义合并或人格推断。记忆提取与语义选择均同步；默认不发起语义选择调用。
- 新增 tests/test_memory_refinement.py、真实模型显式召回/修订/阻止写入用例及 memory-004/005/006 自然场景，仍需人工检查真实模型效果。


## V1.2：综合检索实验（不改变默认模式）

- --long-memory --comprehensive-memory：可选替代 --semantic-memory；先解析最多四个主题、UTC 记录日期闭区间和是否包含已修订陈述，再用 SQLite 过滤并按各主题轮询召回，最多40条候选，模型再选择最多8条（最多允许10条）。无记忆、无检索需求或无候选时跳过不必要的调用。相对 V1.1 最多额外一次调用，无后台工作。
- 记录日期直接来自 turns.created_at，无需迁移已有 SQLite 数据；该日期不是事件发生日期。旧版仅按明确历史回顾需求纳入，active=false 不证明旧内容曾为真。当前表达优先。模型选出的 ID 必须属于受限候选，非法条件/ID 由原 Agent 失败隔离。
- 综合模式记录检索条件、候选 ID、实际召回 ID；注入上下文包含记忆 ID、原话、来源 turn、记录时间与有效状态。没有实现独立的人格画像、持久化认知、自动记忆整理或自主思考。
- 完整性仍受逐轮最多3条、8000字符、模型提取和40条候选限制；词法召回与近期候选补充不能保证长历史语义召回。日期解析依赖模型，UTC 不等同用户本地日历，事件日期不可据此精确过滤。提取提示补充限定条件保留要求，不等于验证了语义真实性。忘记仍是槽位级逻辑删除而非原始对话删除。
- 采用已有 SQLite 与模型接口是为了验证服务价值，暂不新增向量库、主题图谱或认知模型。


## V1.3：已复现缺陷的局部修复

- 原话校验从连续子串升级为保守的完整分句边界检查，并对同句条件、归属及转折标记做启发式检查。原始对话仅在本地用于校验，不将同轮其他信息随记忆扩展发送。旧记录读取时也重新校验；不安全记录不参与召回，不自动删除或修复。此规则不等于语义蕴含判断，可能误拒或漏过复杂表达（含跨句语境、反讽、隐含条件等）。
- 单轮最多12条、单条最多600字符（仍保留8000字符输入上限）。模型提取批次逐项校验，重复槽位全部拒绝；合法独立项在同一事务中用 savepoint 隔离版本冲突，部分拒绝通过 extract_partial 暴露；全部拒绝仍 extract_failed。非法 JSON/超限整批拒绝，数据库异常整批回滚，直接 write 的原子契约不变。仍不能保证模型提取所有重要信息。
- 综合候选池仍为40条。当记录数超限时预留约四分之一名额，对剩余记录按时间均匀取样（包含最旧及最新），其余按主题轮询匹配并用近期记录补足。无额外模型调用。该策略修复已复现的最早零重叠记录被挤出问题，但会牺牲部分字面匹配名额，不能保证所有旧记录或语义相关项被召回；需要真实评测验证净收益。
- 不增加数据库、后台任务、人格推断或自动整理。旧版本文档中的3条、300字符、近期候选回退属于历史基线。
