# 长期记忆 V1（第二阶段实验实现）

目标：超出近期历史后仍能使用用户明确陈述的相关信息，而非构造人格画像。

## 边界与流程

- opt-in：CLI 使用 --long-memory，默认仍为已验收基础 Agent。单用户、同步、SQLite、无额外依赖。
- 对话前：从活跃记忆以中文二字词、英文词、槽位和类别提示词打分，最多注入5条；无命中不注入。
- 回复成功并保存原始对话后：额外一次模型调用，从当前用户原话提取最多3条 JSON 候选；提供最近30个槽位名称及类别，不提供助手回答。超长输入（8000字符以上）不提取。
- 按原文连续子串、类型、长度、槽位、来源 turn ID 严格校验。批量事务写入；同 key 新内容成为当前版本，旧版保留；同值不重复写入。模型不能直接访问数据库。
- memory event 暴露实际读写 ID 和失败类别；记忆异常不覆盖已完成的正常回复。当前不重试或回填。
- /memories 查看活跃记录；/forget <key> 删除槽位所有版本，原始对话仍可能进入近期上下文；/clear 删除对话并级联删除记忆（即使关闭记忆模式）。两者均为 SQLite 逻辑删除而非物理擦除。
- 用户显式纠正可以由提取器复用槽位；V1 不具备可靠的语义冲突判定、自动遗忘或自然语言删除执行能力。
- 事实、经历、主观陈述为原话引用；认知推断放到后续独立研究，暂不存储推断。

## 未解决的问题

词法检索会漏掉同义、隐含或泛化意图，也可能误召回；槽位由模型生成，可能重复或误覆盖。引用真实性检查不等于语义正确性或长期价值；类别与敏感信息过滤依赖提示词，不能保证完全排除。模型上下文中的历史引用可能包含注入攻击，提示隔离仅为初步措施。当前逐轮提取增加成本和同步等待，活跃集合全量扫描只适合研究原型；旧对话不自动迁移。SQLite 未加密，不适合生产或真实敏感数据。

## 验收

- tests/test_long_memory.py：存储、来源验证、更新、删除、重启、模拟模型链路、异常与原有行为。
- tests/live_memory.py：显式要求真实模型写入、召回、修正，验证执行证据及状态；需授权和模型配置。
- evaluation/cases.json memory-001/002/003：自然场景，人工审核，不将标准注入模型。使用 history_turns=0 隔离长期记忆的贡献；输出记忆事件与活跃记录。尚无效果结论。
